# ساخت نصب‌کنندهٔ ویندوز — راهنمای ساده و بدون ترمینال

این پروژه در GitHub Actions روی Windows x64 ساخته می‌شود. کاربر نهایی لازم نیست Rust، Node.js یا Python نصب کند؛ Python bridge پیش از بسته‌بندی با PyInstaller به یک sidecar مستقل تبدیل می‌شود.

## معماری بستهٔ ویندوز

- Workflow ابتدا Python 3.12 و وابستگی‌های `bridge/requirements.txt` را روی runner نصب می‌کند و `bridge/wsm_local_bridge.py` را با PyInstaller در حالت `--onefile` می‌سازد.
- نام خروجی با target triple ویندوز (`x86_64-pc-windows-msvc`) هماهنگ است و در `src-tauri/binaries/` به‌صورت artifact موقت CI قرار می‌گیرد؛ فایل `.spec` یا `.exe` به سورس/ZIP اضافه نشده است.
- Tauri sidecar را از `bundle.externalBin` بسته‌بندی می‌کند. Rust هنگام اجرای اپ فرمان `run` را شروع می‌کند، حداکثر ۱۰ ثانیه پاسخ HTTP روی `127.0.0.1:8765` را برای readiness بررسی می‌کند و هنگام خروج، process group/job object را می‌بندد تا فرایند فرزند PyInstaller باقی نماند. در صورت نبود/خرابی sidecar، پوستهٔ اپ باز می‌شود و قابلیت محلی در دسترس نخواهد بود.
- Python، کتابخانه‌های Python، libusb و DLLهای VC runtime داخل بستهٔ sidecar بررسی می‌شوند؛ Tauri نیز `bundleVCRuntime` را برای runtime برنامه فعال کرده است. Windows 10 روی Surface Pro 5 از هدف x64 پشتیبانی می‌کند؛ نصب یا درایور مدل خاص USB/ZKTeco همچنان به سخت‌افزار و Windows وابسته است.
- این مسیر برای اپ Tauri است و به Python نصب‌شده روی دستگاه نهایی نیاز ندارد. نصب‌گر جداگانهٔ `bridge/install-windows.cmd` برای اجرای مستقل پل کنار PWA/مرورگر باقی است و طبق راهنمای `bridge/README-FA.md` به Python نیاز دارد. دو حالت را هم‌زمان اجرا نکنید: هر دو از پورت ۸۷۶۵ و پیکربندی محلی مشترک استفاده می‌کنند؛ سرویس/Task نصب قدیمی را پیش از اجرای Tauri متوقف کنید.

## یک‌بار: پروژه را در GitHub قرار دهید

1. فایل ZIP پروژه را دانلود و در ویندوز از حالت فشرده خارج کنید.
2. در GitHub یک مخزن تازه بسازید؛ می‌توانید آن را Private نگه دارید.
3. GitHub Desktop را نصب کنید، وارد حساب شوید و مخزن را Clone کنید.
4. محتویات داخل پوشهٔ `wp-store-manager` استخراج‌شده را در ریشهٔ مخزن کپی کنید و فایل‌های هم‌نام را جایگزین کنید.
5. در ریشهٔ مخزن، `package.json`، `wsm-app`، `src-tauri`، `.github` و همین راهنما را ببینید.
6. در GitHub Desktop commit و سپس Push کنید.

## هر بار: فایل نصب را دانلود کنید

1. در مخزن GitHub، زبانهٔ **Actions** را باز کنید. هر Push ساخت را شروع می‌کند؛ اجرای دستی **Run workflow** هم در دسترس است.
2. منتظر بمانید تا **Build Windows installers** سبز شود. اگر ساخت شکست خورد، گزارش مرحلهٔ PyInstaller، آزمون DLLها یا Tauri را باز کنید. workflow وجود هر دو خروجی و حجم حداقل ۱۰۰ مگابایت را بررسی می‌کند و SHA-256 را در خلاصهٔ اجرا می‌نویسد؛ فایل کوچک/ناقص بارگذاری نمی‌شود.
3. Artifact با نام `wp-store-manager-windows-installers` را دانلود و Extract کنید.
4. یکی از نصب‌کننده‌های NSIS با پسوند `.exe` یا MSI با پسوند `.msi` را اجرا کنید؛ نصب هر دو لازم نیست. NSIS هر دو میانبر Start Menu و Desktop را می‌سازد.

## نکته‌های کوتاه

- WebView2 با `offlineInstaller` همراه هر دو نصب‌کنندهٔ NSIS/MSI بسته‌بندی می‌شود؛ طبق مستند Tauri حدود ۱۲۷ مگابایت به هر نصب‌کننده اضافه می‌کند و نصب بدون اینترنت را ممکن می‌سازد. کف نسخهٔ `109.0.1518.78` نیز بررسی می‌شود. به همین دلیل فایل واقعی نصب باید بزرگ باشد، نه چند کیلوبایت.
- نصب‌کننده‌ها امضای دیجیتال ناشر ندارند؛ Windows SmartScreen ممکن است هشدار ناشر ناشناس نشان دهد.
- داده‌های آفلاین فعلی اپ از IndexedDB استفاده می‌کنند. SQLite در پروژهٔ Tauri تنظیم شده، اما انتقال داده‌های IndexedDB به SQLite جداگانه لازم است.
- جفت‌سازی پل تازه از داخل اپ دسکتاپ، با نشست مدیر و گزینهٔ «اتصال دستگاه ← جفت‌سازی امن با WordPress» انجام می‌شود؛ Access Key در پنجرهٔ مستقل Local Bridge برای جفت‌سازی تازه استفاده نمی‌شود. پس از Pair، مجوز `club.bridge` را برای دستگاه جدید در پیشخوان فعال کنید.

## ساخت محلی (توسعه‌دهندگان)

پیش‌نیازها: Node.js و npm، Rust stable، و Python 3.12 یا جدیدتر؛ برای نصب‌کننده‌های ویندوز، ساخت را روی Windows x64 اجرا کنید. از ریشهٔ مخزن:

```bash
npm install
npm run tauri build
```

فرمان‌های Tauri به‌طور خودکار، پیش از build، `wsm-app/dist` را با Vite می‌سازند و bridge را با PyInstaller در محیط مجازی `bridge/.venv-tauri` بسته‌بندی می‌کنند. sidecar با target triple همان سیستم در `src-tauri/binaries/` قرار می‌گیرد؛ نیازی به اجرای دستی مرحلهٔ PowerShell یا ذخیرهٔ باینری در ZIP نیست. اجرای اول برای نصب وابستگی‌های Node و Python به اینترنت نیاز دارد؛ خروجی‌های محلی در `.gitignore` قرار دارند.

برای کامپایل محلی روی Linux یا macOS بدون ساخت installerهای Windows، از این فرمان استفاده کنید:

```bash
npm run tauri -- build --no-bundle
```

ساخت installerهای NSIS و MSI همچنان در Windows x64 (یا workflow ویندوز) انجام می‌شود.

### اتصال اولین اجرا

پس از نصب نسخهٔ دسکتاپ، اپ در اجرای اول صفحهٔ داخلی «اتصال به فروشگاه» را نشان می‌دهد؛ نیازی نیست ابتدا همان صفحه را در مرورگر سایت باز کنید. نشانی سایت و Access Key را وارد کنید. دکمه‌های «تست اینترنت» (دسترسی به `api.ipify.org`) و «تست اتصال به سایت» (REST API افزونه) علت مشکل را جدا می‌کنند. Access Key فقط سایت را اعتبارسنجی می‌کند؛ ورود کارمند پس از آن انجام می‌شود. برای تغییر فروشگاه، ابتدا عملیات آفلاین فروشگاه قبلی را همگام کنید.
